Predictive Modeling: Evaluation and Improvement Methods

Overview

Learning Objectives:

  • Understand the fundamentals of predictive modeling
  • Learn different methods for evaluating model performance
  • Identify common modeling problems and their solutions
  • Apply model improvement techniques using R and tidymodels
  • Make informed decisions about model selection and tuning

What is Predictive Modeling?

Definition: Predictive modeling uses statistical and machine learning techniques to predict future outcomes based on historical data.

Key Components:

  1. Training Data: Historical data used to build the model
  2. Features (Predictors): Input variables used for prediction
  3. Target Variable: The outcome we want to predict
  4. Model Algorithm: The mathematical approach (e.g., linear regression, random forest)
  5. Predictions: The model’s outputs for new data

Two Main Types:

  • Regression: Predicting continuous values (e.g., temperature, species abundance)
  • Classification: Predicting categories (e.g., species presence/absence, habitat type)

The Fundamental Challenge: Generalization

The Goal: Build a model that performs well on new, unseen data

The Problem: Models can perform well on training data but poorly on new data

Why This Matters:

  • A model that only works on training data is useless for predictions
  • We need models that capture true patterns, not random noise
  • This is the essence of the generalization problem

Example from Environmental Science:

  • Training on water quality data from 2020
  • Want to predict water quality in 2025
  • Model must learn general patterns, not year-specific quirks

Problem #1: Overfitting

What is Overfitting?

Overfitting occurs when a model learns the training data too well, including random noise and specific details that don’t generalize to new data.

Characteristics:

  • High performance on training data
  • Poor performance on test/new data
  • Model is too complex for the amount of data
  • Captures noise instead of signal

Real-World Analogy:

Like a student who memorizes specific exam questions instead of understanding concepts—they’ll fail when questions are worded differently.

Symptoms:

  • Large gap between training and validation accuracy
  • Model has too many parameters relative to data size
  • Unstable predictions (small input changes cause large output changes)

Problem #1: Overfitting (Example)

R Example: Polynomial Regression with Tidymodels

Code 
library(tidymodels)
library(ggplot2)
theme_set(theme_minimal())

# Generate data with noise
set.seed(42)
x <- seq(0, 10, by = 0.5)
y_true <- 2 * x + 5
y_observed <- y_true + rnorm(length(x), sd = 3)
train_data <- tibble(x = x, y = y_observed)

# Simple linear model (appropriate)
simple_spec <- linear_reg() %>%
  set_engine("lm")

simple_fit <- simple_spec %>%
  fit(y ~ x, data = train_data)

# Overfit model (polynomial degree 15)
overfit_spec <- linear_reg() %>%
  set_engine("lm")

overfit_fit <- overfit_spec %>%
  fit(y ~ poly(x, 15), data = train_data)

# Generate predictions
x_new <- seq(0, 10, by = 0.1)
pred_data <- tibble(x = x_new)

pred_data$simple <- predict(simple_fit, pred_data)$.pred
pred_data$overfit <- predict(overfit_fit, pred_data)$.pred

# Plot
ggplot() +
  geom_point(data = train_data, aes(x, y), size = 3) +
  geom_line(data = pred_data, aes(x, simple), color = "blue", linewidth = 1) +
  geom_line(data = pred_data, aes(x, overfit), color = "red", linewidth = 1) +
  labs(title = "Simple (blue) vs Overfit (red) Model")

What You’ll See: The overfit model wiggles through every point but won’t generalize well.

Problem #2: Underfitting

What is Underfitting?

Underfitting occurs when a model is too simple to capture the underlying patterns in the data.

Characteristics:

  • Poor performance on both training and test data
  • Model lacks sufficient complexity
  • Fails to capture important relationships
  • Too much bias toward simplicity

Real-World Analogy:

Like trying to predict species diversity using only one environmental variable when multiple factors matter.

Symptoms:

  • Low accuracy on training data
  • Model predictions are systematically wrong
  • Clear patterns in residual plots
  • Important features are ignored

The Bias-Variance Tradeoff

Two Sources of Prediction Error:

  1. Bias: Error from overly simplistic assumptions
    • High bias → underfitting
    • Model consistently misses the true pattern
  2. Variance: Error from sensitivity to training data fluctuations
    • High variance → overfitting
    • Model changes dramatically with different training samples

The Tradeoff: - Increasing model complexity reduces bias but increases variance - Decreasing complexity reduces variance but increases bias - Goal: Find the sweet spot that minimizes total error

Formula:

Total Error = Bias² + Variance + Irreducible Error

Bias-Variance Tradeoff (Visualization)

R Example with Tidymodels:

Code 
library(tidymodels)
library(ggplot2)

# Simulate model complexity vs error
complexity <- seq(1, 20, by = 0.5)
bias <- 10 / complexity + 0.5
variance <- 0.1 * complexity
total_error <- bias + variance

df <- tibble(
  Complexity = rep(complexity, 3),
  Error = c(bias, variance, total_error),
  Type = rep(c("Bias²", "Variance", "Total Error"), each = length(complexity))
)

ggplot(df, aes(x = Complexity, y = Error, color = Type)) +
  geom_line(linewidth = 1.5) +
  geom_vline(
    xintercept = complexity[which.min(total_error)],
    linetype = "dashed",
    color = "gray"
  ) +
  labs(
    title = "Bias-Variance Tradeoff",
    x = "Model Complexity",
    y = "Prediction Error"
  ) +
  theme_minimal(base_size = 14)

Key Insight: The optimal model complexity minimizes total error, not bias or variance individually.

Solution #1: Train-Test Split

What is it?

Splitting your data into separate sets for training and evaluation ensures honest assessment of model performance.

The Method:

  • Training Set (70-80%): Used to fit the model
  • Test Set (20-30%): Used to evaluate final performance
  • Test data is never seen during training

Why It Works:

  • Simulates real-world prediction scenario
  • Prevents overfitting to the entire dataset
  • Provides unbiased performance estimate

Important: The split should be random to avoid systematic bias.

Solution #2: K-Fold Cross-Validation

What is it?

A more robust evaluation method that uses multiple train-test splits to get a better estimate of model performance.

The Method:

  1. Divide data into K equal parts (folds), typically K=5 or K=10
  2. For each fold:
    • Train on K-1 folds
    • Test on the remaining fold
  3. Average the performance across all K iterations

Why It’s Better Than Single Split:

  • More stable performance estimate
  • Uses all data for both training and testing
  • Reduces impact of lucky/unlucky splits
  • Better for smaller datasets

Common Choices:

  • K=10: Most common, good balance
  • K=5: Faster, still reliable
  • Leave-One-Out (LOO): Maximum data use, computationally expensive

Evaluation Metrics: Regression

For Continuous Predictions (temperature, biomass, etc.)

1. Mean Absolute Error (MAE)

MAE = mean(|actual - predicted|)
  • Easy to interpret: average prediction error in original units
  • Not sensitive to outliers

2. Root Mean Squared Error (RMSE)

RMSE = sqrt(mean((actual - predicted)²))
  • Penalizes large errors more than MAE
  • Same units as target variable
  • More commonly used than MAE

3. R-squared (R²)

R² = 1 - (SS_residual / SS_total)
  • Proportion of variance explained by model
  • Ranges from 0 to 1 (higher is better)
  • Can be negative for very poor models

When to Use Each:

  • MAE: When all errors are equally important
  • RMSE: When large errors are particularly problematic
  • R²: When comparing models or understanding explained variance

Evaluation Metrics: Classification

For Categorical Predictions (species, present/absent, etc.)

The Confusion Matrix:

                  Predicted
                Positive  Negative
Actual Positive    TP        FN
       Negative    FP        TN

Key Metrics:

1. Accuracy: Overall correctness

Accuracy = (TP + TN) / (TP + TN + FP + FN) = P(correct predictions)

2. Specificity: Of all actual negatives, how many did we correctly identify?

Specificity = TN / (TN + FP) 
            = P(predicted negative | actual negative)

3. Recall (Sensitivity): Of all actual positives, how many did we catch?

Recall = TP / (TP + FN) 
       = P(predicted positive | actual positive)

4. F1-Score: Harmonic mean of precision and recall

F1 = 2 × (Precision × Recall) / (Precision + Recall)

5. Precision: When model predicts positive, how often is it correct?

Precision = TP / (TP + FP) 
          = P(actual positive | predicted positive)
          = Positive Predictive Value

Note

Note that Precision is a “forward-looking” metric, while Recall/Sensitivity and Specificity are “backward-looking”, in the sense that we need to know the truth first and then see what we achieved.

Warning

You can have a test/predictive model with very high sensitivity and specificity but low precision if the prevalence of the positive class is very low. This is often used as an example in medical testing to say that a test with 99% sensitivity and 99% specificity can still have a low positive predictive value (precision) if the disease is rare.

This is also an application of Bayes Rule

Classification Metrics: When to Use Each

Accuracy

  • Use when: Classes are balanced
  • Problem: Misleading with imbalanced data
  • Example: 95% accuracy seems good, but if 95% of samples are negative, predicting “always negative” achieves this!

Precision

  • Use when: False positives are costly
  • Example: Predicting disease presence—don’t want to unnecessarily alarm patients

Recall

  • Use when: False negatives are costly
  • Example: Detecting invasive species—missing one could be disastrous

F1-Score

  • Use when: Need balance between precision and recall
  • Example: General classification where both error types matter

Key Insight: Choose metrics based on the cost of errors in your specific context.

Advanced Metric: ROC Curve and AUC

What is ROC?

ROC (Receiver Operating Characteristic) curve visualizes classifier performance across all possible decision thresholds.

Components:

  • X-axis: False Positive Rate (1 - Specificity)
  • Y-axis: True Positive Rate (Recall/Sensitivity)
  • Each point: Performance at different threshold

AUC (Area Under Curve):

  • Single number summarizing ROC curve
  • Ranges from 0.5 (random guessing) to 1.0 (perfect)
  • Interpretation: Probability that model ranks a random positive instance higher than a random negative instance

Why It’s Useful:

  • Threshold-independent evaluation
  • Good for imbalanced datasets
  • Easy to compare multiple models

What is Precision-Recall Curve?

Plots Precision vs. Recall at various threshold settings, useful for imbalanced datasets.

Why Use It?

  • Focuses on positive class performance
  • More informative than ROC for imbalanced datasets
  • Helps choose optimal threshold

AUC-PR:

  • Higher values indicate better performance
  • Ranges from 0 to 1

Solution #3: Regularization

What is Regularization?

Regularization adds a penalty to the model’s loss function to discourage overly complex models, helping prevent overfitting.

How It Works:

  • Original goal: Minimize prediction error
  • Regularized goal: Minimize prediction error + penalty for complexity

Two Main Types:

1. Ridge Regression (L2 Regularization)

Loss = MSE + λ × Σ(coefficients²)
  • Shrinks all coefficients toward zero
  • Never sets coefficients exactly to zero
  • Good when all features might be relevant

2. Lasso Regression (L1 Regularization)

Loss = MSE + λ × Σ|coefficients|
  • Can set some coefficients exactly to zero
  • Performs automatic feature selection
  • Good when some features are irrelevant

The λ (Penalty) Parameter: Controls strength of regularization (higher = more penalty)

Regularization: Ridge vs Lasso

Ridge Regression (L2):

Advantages:

  • Handles multicollinearity well
  • Keeps all features in model
  • Typically more stable

When to Use:

  • All features potentially relevant
  • Features are correlated
  • Interpretability less important

Lasso Regression (L1):

Advantages:

  • Automatic feature selection
  • Produces simpler, more interpretable models
  • Better for high-dimensional data

When to Use:

  • Many irrelevant features
  • Want sparse model
  • Need interpretability

Elastic Net:

  • Combines both L1 and L2 (mixture parameter)
  • Best of both worlds
  • Extra hyperparameter to tune

Regularization: Ridge Example

  step_normalize(all_predictors())

# Create workflow

  add_model(ridge_spec) %>%

Solution #4: Feature Selection

What is Feature Selection?

Choosing a subset of relevant features and removing irrelevant or redundant ones to improve model performance and interpretability.

Why It Matters:

  • Reduces overfitting (fewer parameters to learn)
  • Improves model interpretability
  • Decreases computational cost
  • Can improve prediction accuracy

Solution #4: Feature Selection

Three Main Approaches:

1. Filter Methods

  • Use statistical tests to rank features
  • Independent of model
  • Fast but ignores feature interactions
  • Examples: correlation, variance threshold

2. Wrapper Methods

  • Use model performance to evaluate subsets
  • Considers feature interactions
  • Computationally expensive
  • Examples: recursive feature elimination

3. Embedded Methods

  • Feature selection during model training
  • Balance between filter and wrapper
  • Examples: Lasso, Random Forest importance

Solution #5: Ensemble Methods - Bagging

What is Bagging?

Bagging (Bootstrap Aggregating) trains multiple models on different random subsets of data and averages their predictions.

How It Works:

  1. Create K bootstrap samples (sampling with replacement)
  2. Train a model on each sample independently
  3. Aggregate predictions (average for regression, vote for classification)

Why It Works:

  • Reduces variance without increasing bias
  • Particularly effective for high-variance models (e.g., decision trees)
  • Models learn different aspects from different samples

Random Forest:

  • Most popular bagging method
  • Bags decision trees
  • Also randomizes features at each split
  • Excellent general-purpose algorithm

Key Benefit: Prevents overfitting by averaging out individual model quirks.

Solution #5: Ensemble Methods - Boosting

What is Boosting?

Boosting sequentially trains models, with each new model focusing on correcting errors made by previous models.

How It Works:

  1. Train initial model on all data
  2. Identify misclassified/poorly predicted samples
  3. Train next model with more weight on those difficult samples
  4. Repeat, building sequence of models
  5. Final prediction is weighted combination of all models

Why It Works:

  • Reduces both bias and variance
  • Forces models to learn difficult patterns
  • Each model specializes in different aspects

Popular Algorithms:

  • AdaBoost: Adjusts sample weights
  • Gradient Boosting: Fits to residual errors
  • XGBoost/LightGBM: Optimized implementations

Key Difference from Bagging: Sequential (not parallel) with focus on previous errors.

Solution #6: Hyperparameter Tuning

What are Hyperparameters?

Parameters set before training that control the learning process (not learned from data).

Examples:

  • Number of trees in random forest
  • Learning rate in gradient boosting
  • Regularization strength (λ)
  • Number of neighbors in k-NN
  • Tree depth, min samples per leaf

Why Tune Them?

  • Default values rarely optimal
  • Proper tuning significantly improves performance
  • Can mean difference between mediocre and excellent model

Solution #6: Hyperparameter Tuning

Two Main Approaches:

1. Grid Search

  • Tests all combinations of specified values
  • Exhaustive but thorough
  • Computationally expensive
  • Best when parameter space is small

2. Random Search

  • Tests random combinations
  • More efficient for large parameter spaces
  • Often finds good solutions faster
  • Recommended for initial exploration

Putting It All Together: Complete Workflow

Step-by-Step Predictive Modeling Process:

1. Data Preparation

  • Clean data, handle missing values
  • Split into train/test sets
  • Create cross-validation folds

2. Initial Model Training

  • Start with simple baseline models
  • Use cross-validation for evaluation
  • Check for obvious overfitting/underfitting

3. Feature Engineering

  • Create relevant features using recipes
  • Remove irrelevant/redundant features
  • Use domain knowledge

4. Model Selection

  • Try multiple algorithms
  • Compare using consistent metrics
  • Consider bias-variance tradeoff

5. Hyperparameter Tuning

  • Use grid, random, or Bayesian search
  • Optimize on validation/CV folds
  • Avoid tuning on test set

6. Final Evaluation

  • Evaluate best model on held-out test set using last_fit()
  • Report multiple relevant metrics
  • Check residuals/error patterns

What is Calibration?

Calibration assesses how well predicted probabilities reflect actual outcomes.

  • Important for classification tasks
  • A well-calibrated model’s predicted probabilities match observed frequencies

How to Check Calibration:

  • Calibration plots (predicted vs observed)
  • Brier score (lower is better)

library(ggplot2)
library(probably)
set.seed(123)
# Prepare data
# Using Pima Indians diabetes dataset
data("PimaIndiansDiabetes2", package = "mlbench")

diabetes_data <- PimaIndiansDiabetes2 %>%
  na.omit() %>%
  mutate(diabetes = as.factor(ifelse(diabetes == "pos", "pos", "neg")))

# Split data
diabetes_split <- initial_split(diabetes_data, prop = 0.8, strata = diabetes)
diabetes_train <- training(diabetes_split)
diabetes_test <- testing(diabetes_split)

# Define logistic regression model
log_reg_spec <- logistic_reg() %>%
  set_engine("glm") %>%
  set_mode("classification")

# Create workflow
log_reg_workflow <- workflow() %>%
  add_model(log_reg_spec) |>
  add_formula(diabetes ~ .)

# Fit model
log_reg_fit <- log_reg_workflow %>%
  fit(diabetes_train)

# Predictions on test set
test_results <- diabetes_test %>%
  bind_cols(predict(log_reg_fit, diabetes_test, type = "prob")) %>%
  bind_cols(predict(log_reg_fit, diabetes_test))

test_results |>
  cal_plot_breaks(
    truth = diabetes,
    estimate = .pred_pos,
    event_level = 'second'
  )
test_results |>
  cal_plot_windowed(
    truth = diabetes,
    estimate = .pred_pos,
    event_level = 'second',
    window_size = 0.2
  )

Common Mistakes to Avoid

1. Data Leakage

  • Problem: Information from test set leaks into training
  • Example: Normalizing data before splitting
  • Solution: Always split first, then preprocess (use recipes!)

2. Overfitting to Validation Set

  • Problem: Tuning hyperparameters repeatedly on same validation set
  • Solution: Use nested cross-validation or separate validation set

3. Ignoring Class Imbalance

  • Problem: High accuracy on imbalanced data is misleading
  • Solution: Use appropriate metrics (precision, recall, F1, AUC) and stratified sampling

4. Not Checking Assumptions

  • Problem: Using linear models on non-linear relationships
  • Solution: Visualize data, check residuals, consider transformations

5. Test Set Contamination

  • Problem: Trying many models and reporting best result on test set
  • Solution: Final test set evaluation should be done exactly once with last_fit()

6. Forgetting to Set Seeds

  • Problem: Results not reproducible
  • Solution: Set seed before any random operation

Decision Guide: Which Method When?

Problem: Overfitting

  • ✓ Use cross-validation with fit_resamples()
  • ✓ Apply regularization (Ridge/Lasso with tune())
  • ✓ Feature selection (step_corr(), vip, lasso)
  • ✓ Get more training data
  • ✓ Use ensemble methods (bagging)
  • ✓ Reduce model complexity

Problem: Underfitting

  • ✓ Use more complex model
  • ✓ Add relevant features (recipes)
  • ✓ Reduce regularization penalty
  • ✓ Use ensemble methods (boosting)
  • ✓ Increase trees/iterations

Problem: Limited Data

  • ✓ Use domain knowledge
  • ✓ Use cross-validation (vfold_cv())
  • ✓ Use simpler models
  • ✓ Strong regularization
  • ✓ Feature selection

Problem: High-Dimensional Data

  • ✓ Lasso for feature selection
  • ✓ Random Forest (handles many features)
  • ✓ step_pca() for dimensionality reduction

Problem: Imbalanced Classes

  • ✓ Use precision, recall, F1, AUC
  • ✓ Stratified sampling (strata argument)
  • ✓ step_downsample() or step_upsample()

  3. Overfitting and underfitting are the two main pitfalls

Questions & Discussion

Common Questions:

  1. How much data do I need?

    • Depends on problem complexity
    • Rule of thumb: 10+ samples per feature
    • Cross-validation helps with smaller datasets

  2. Which algorithm should I start with?

    • Regression: linear_reg() → regularization → rand_forest()
    • Classification: logistic_reg() → rand_forest() → boost_tree()

  3. How do I know if my model is good enough?

    • Compare to baseline (e.g., mean prediction)
    • Consider domain requirements
    • Check if performance is stable across CV folds

Questions & Discussion

  1. What metrics should I use?

    • Classification: accuracy, precision, recall, F1 score
    • Regression: RMSE, MAE, R-squared
    • Choose based on business goals and costs

  2. How do I prevent data leakage?

    • Always split data FIRST
    • Use recipes (preprocessing happens automatically per fold)
    • Never touch test set until final evaluation with last_fit()
