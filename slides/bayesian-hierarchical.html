Why Hierarchical Models?

Environmental data naturally has structure

— sites within regions, measurements over time, species within ecosystems. Hierarchical models respect this structure.

What are Hierarchical Models?

Definition: Statistical models that account for data collected at multiple levels or with nested structure.

Also Known As:

  • Mixed-effects models
  • Multilevel models
  • Random effects models
  • Nested models

Key Idea

Some observations are more similar to each other than to others because they share common features (same site, same species, same year).

Example in Environmental Science:

  • Water quality measurements from multiple lakes
  • Each lake has multiple sampling sites
  • Each site measured multiple times
  • Measurements within a lake are more similar than across lakes

The Problem: Clustered Data

Real-World Scenario:

You’re studying mercury contamination in fish across 20 lakes. You catch 10 fish per lake and measure mercury levels and length of each fish. You want to build a model that relates fish length to mercury concentration.

Question: How should we analyze these 200 measurements?

The Issue:

  • Fish from the same lake are more similar than fish from different lakes
  • They share the same water chemistry, food web, temperature
  • Standard regression assumes all observations are independent
  • Ignoring lake structure leads to incorrect conclusions

Consequences of Ignoring Structure

  • Underestimated standard errors → inflated Type I error rates
  • False confidence in results
  • Poor predictions for new lakes
  • Missing important sources of variation

The Pooling Problem

Three Approaches to Handling Groups:

1. Complete Pooling (Ignore Groups)

  • Treat all fish as if they came from one giant lake
  • Simple but wrong
  • Ignores important variation between lakes

2. No Pooling (Separate Models)

  • Fit completely separate model for each lake
  • 20 independent analyses
  • Loses information, can’t compare lakes
  • Terrible for lakes with few fish

3. Partial Pooling (Hierarchical Model)

  • Model each lake separately BUT
  • Share information across lakes
  • Best of both worlds!

Let’s explore each approach…

Complete Pooling: Ignore the Structure

The Model:

\[ \text{mercury}_i = \beta_0 + \beta_1 \times \text{length}_i + \epsilon_i \] where i indexes fish.

What This Means:

  • One grand mean (\(\beta_0\)) for all lakes
  • Same relationship (\(\beta_1\)) everywhere
  • Assumes all lakes are identical

When It Might Be OK:

  • Groups are truly irrelevant to the question
  • Interest is only in population average
  • Rarely appropriate for environmental data

Problems:

  • Clearly wrong—lakes differ in baseline mercury
  • Pretends we have 200 independent fish
  • Standard errors too small (overconfident)
  • Can’t make lake-specific predictions

No Pooling: Treat Groups Independently

The Model:

\[ \text{mercury}_{ij} = \beta_{0j} + \beta_1 \times \text{length}_{ij} + \epsilon_{ij} \] where j indexes lake and i indexes fish within lake j. This is equivalent to fitting 20 separate regressions

What This Means:

  • Each lake gets its own intercept (β₀j)
  • 20 separate analyses
  • No information shared between lakes

When It Might Be OK:

  • Groups are fundamentally different
  • Abundant data in each group
  • No interest in new groups
  • Sometimes reasonable but wasteful

Problems:

  • Estimates for small lakes are very uncertain
  • Can’t make predictions for new lakes
  • Ignores fact that lakes come from common distribution
  • Extreme estimates for unusual lakes

Partial Pooling: The Hierarchical Solution

The Model:

Level 1 (fish): \(\text{mercury}_{ij} = \alpha_j + \beta × \text{length}_{ij} + \varepsilon_{ij}\)
Level 2 (lake): \(\alpha_j \sim \text{Normal}(\mu_\alpha, \sigma_\alpha)\)

where j indexes lake and i indexes fish within lake j.

What This Means:

  • Each lake has its own intercept (\(\alpha_j\))
  • BUT lake intercepts come from a common distribution
  • Lakes with little data “borrow strength” from others
  • Information sharing!

Why This Works:

  • Respects that lakes differ (random intercepts)
  • Recognizes lakes are samples from population
  • Automatically balances group vs. population information
  • Produces “shrinkage” toward population mean

This is What Makes Hierarchical Models Powerful!

Shrinkage: The Magic of Partial Pooling

What is Shrinkage?

Estimates for individual groups are pulled toward the overall mean, with the amount of pull depending on:

  1. How much data in that group
  2. How variable the group is
  3. How different it is from other groups

The Formula (Conceptually):

group_estimate = w × group_data + (1-w) × population_mean

where w depends on sample size and variability

Practical Example

  • Lake with 2 fish: mostly uses population info (w ≈ 0.2)
  • Lake with 50 fish: mostly uses own data (w ≈ 0.9)

library(rstanarm)
library(ggplot2)
library(dplyr)

# Set seed for reproducibility
set.seed(123)

# Create simulated lake mercury data with varying sample sizes
# This reflects the "8 lakes with different sample sizes" concept
lake_info <- data.frame(
  lake = paste0("Lake_", LETTERS[1:8]),
  sample_size = c(50, 30, 20, 15, 10, 5, 3, 2), # Varying sample sizes
  true_intercept = c(2.0, 2.8, 1.5, 3.2, 1.8, 2.5, 1.2, 3.5) # True lake effects
)

# Generate fish data
fish_data <- map_dfr(1:nrow(lake_info), function(i) {
  lake <- lake_info$lake[i]
  n <- lake_info$sample_size[i]
  true_int <- lake_info$true_intercept[i]

  data.frame(
    lake = lake,
    fish_id = 1:n,
    length = rnorm(n, mean = 25, sd = 5), # Fish length (cm)
    mercury = rnorm(n, mean = true_int + 0.05 * rnorm(n, 25, 5), sd = 0.3)
  )
})

# 1. COMPLETE POOLING (ignore lake structure)
complete_pool <- stan_glm(
  mercury ~ length,
  data = fish_data,
  family = gaussian(),
  chains = 4,
  iter = 1000,
  refresh = 0, # Suppress output
  seed = 123
)

# 2. NO POOLING (separate models for each lake)
no_pool_estimates <- fish_data %>%
  group_by(lake) %>%
  summarise(
    intercept = mean(mercury - 0.05 * length), # Crude estimate
    n_fish = n(),
    .groups = 'drop'
  )

# 3. PARTIAL POOLING (hierarchical model)
partial_pool <- stan_glmer(
  mercury ~ length + (1 | lake),
  data = fish_data,
  family = gaussian(),
  chains = 4,
  iter = 1000,
  refresh = 0,
  seed = 123
)

# Extract estimates for comparison
complete_pool_int <- fixef(complete_pool)[1]
partial_pool_ints <- coef(partial_pool)$lake[, 1]
population_mean <- fixef(partial_pool)[1]

# Create comparison data frame
comparison_data <- data.frame(
  lake = lake_info$lake,
  sample_size = lake_info$sample_size,
  true_intercept = lake_info$true_intercept,
  complete_pooling = complete_pool_int,
  no_pooling = no_pool_estimates$intercept,
  partial_pooling = partial_pool_ints,
  population_mean = population_mean
)

# Calculate shrinkage factor (w) - how much each lake relies on its own data
comparison_data <- comparison_data %>%
  mutate(
    shrinkage_factor = abs(no_pooling - population_mean) /
      abs(partial_pooling - population_mean),

  )

When to Use Hierarchical Models

You Should Use Hierarchical Models When:

✓ Nested/Grouped Structure

  • Multiple sites within regions
  • Repeated measurements on same individuals/locations
  • Multiple species, plots, watersheds

✓ Interest in Group-Level Variation

  • How much do lakes differ in baseline mercury?
  • What’s the variance between sites?
  • Are groups meaningfully different?

When to Use Hierarchical Models

You Should Use Hierarchical Models When:

✓ Predictions for New Groups

  • Predict mercury for an unsampled lake
  • Estimate values for new sites
  • Generalize beyond observed groups

✓ Unbalanced Data

  • Some groups have many observations, others few
  • Hierarchical models handle this gracefully
  • No need to throw away data!

When to Use Hierarchical Models (Examples)

Environmental Science Examples:

1. Spatial Hierarchical Structure

  • Problem: Measuring nitrogen runoff from 50 farms across 5 watersheds
  • Why Hierarchical: Farms within a watershed share hydrology, soil, climate
  • Model: Farm-level measurements nested in watersheds

2. Temporal Hierarchical Structure

  • Problem: Species counts at 20 sites over 10 years
  • Why Hierarchical: Repeated measures at same sites aren’t independent
  • Model: Yearly observations nested within sites

When to Use Hierarchical Models (Examples)

Environmental Science Examples:

3. Taxonomic Hierarchical Structure

  • Problem: Testing pollutant effects on 30 fish species from 4 families
  • Why Hierarchical: Species within family share biology
  • Model: Species nested within families

4. Multi-Level Spatial

  • Problem: Tree growth in plots within forests within ecoregions
  • Why Hierarchical: Three levels of grouping!
  • Model: Plots within forests within regions

Problem: Which Model for Bird Surveys?

Scenario:

You conduct bird surveys at 30 sites across a mountain gradient. Each site is visited 4 times during breeding season.

Data Structure:

  • 30 sites × 4 visits = 120 observations
  • Want to relate bird abundance to elevation

Question: What model should you use?

A. Standard Linear Model (ignore sites)

abundance ~ elevation

B. Fixed Effects for Sites

abundance ~ elevation + site

C. Hierarchical Model

Level 1: abundance_ij ~ elevation_j + α_j
Level 2: α_j ~ Normal(μ, σ)

Answer: C! Why?

  • Visits within sites are not independent (repeated measures)
  • Want to generalize to other sites on mountain
  • Sites are random sample from population of possible sites
  • Interested in site-to-site variation

Bayesian Approach to Hierarchical Models

Why Bayesian for Hierarchical Models?

  1. Natural Framework

    • Hierarchical structure maps directly to Bayesian model
    • Hyperparameters get hyperpriors—it’s all just probability!

  2. Handles Complexity

    • Complex models fit without approximations
    • Correctly propagates uncertainty through levels

  3. Small Sample Sizes

    • Works well even with few groups or observations per group
    • No asymptotic assumptions needed

  4. Interpretable Uncertainty

    • Full posterior distributions for everything
    • Credible intervals have direct interpretation
    • Uncertainty about variance components

  5. Predictive Distributions

    • Easy to predict for new groups
    • Accounts for all sources of uncertainty

Bayesian Building Blocks

Quick Bayesian Refresher:

Bayes’ Theorem:

Posterior ∝ Likelihood × Prior
P(θ|data) ∝ P(data|θ) × P(θ)

Components:

  • Likelihood: P(data|θ) = How likely are the data given parameters?
  • Prior: P(θ) = What do we believe before seeing data?
  • Posterior: P(θ|data) = Updated beliefs after seeing data

In Hierarchical Models:

  • Parameters at each level get distributions
  • Hyperparameters control group-level distributions
  • Everything estimated simultaneously

Practical Interpretation:

  • 95% Credible Interval: “Given the data, there’s a 95% probability the parameter is in this range”
  • Direct probability statements!

Hierarchical Model Structure

General Form:

Level 1 (Observation Level):

\[ y_{ij} \sim \text{Normal}(\mu_{ij}, \sigma_{y}) \\ \mu_{ij} = \alpha_j + \beta \times x_{ij} \]

Level 2 (Group Level):

\[ \alpha_j \sim \text{Normal}(\mu_{\alpha}, \sigma_{\alpha}) \]

Level 3 (Population Level / Priors):

\[ \mu_{\alpha} \sim \text{Normal}(0, 10) \\ \sigma_{\alpha} \sim \text{Cauchy}(0, 2.5) \\ \beta \sim \text{Normal}(0, 5) \\ \sigma_{y} \sim \text{Cauchy}(0, 2.5) \]

What This Means:

  • Observations vary within groups (\(\sigma_y\))
  • Groups vary within population (\(\sigma_{\alpha}\))
  • Both sources of variation estimated
  • Priors express prior knowledge (often weakly informative)

Fixed vs Random Effects

Terminology (Often Confusing!):

Fixed Effects:

  • Parameters we estimate and care about
  • Examples: slope of elevation, effect of temperature
  • Same across all groups (though can vary in mixed models)

Random Effects:

  • Parameters that vary by group
  • Assume groups drawn from population distribution
  • Examples: lake-specific intercepts, site-level variation
  • Focus is on the distribution (mean and variance), not individual values

Helpful Distinction:

  • Fixed: “These specific effects”
  • Random: “Variation among similar things”

In Environmental Models:

  • Fixed: covariate effects (temperature, elevation, treatment)
  • Random: site effects, year effects, species effects
  • Both can be in the same model!

Introduction to rstanarm

What is rstanarm?

An R package that fits Bayesian regression models using Stan, with syntax similar to base R.

Key Features:

  • Familiar formula syntax (lm, lmer style)
  • Pre-compiled models (fast!)
  • Sensible default priors
  • Easy to use, hard to misuse

Installation:

install.packages("rstanarm")
library(rstanarm)

Basic Syntax:

# Standard regression
model <- stan_glm(y ~ x, data = mydata)

# Hierarchical model (like lme4)
model <- stan_glmer(y ~ x + (1 | group), data = mydata)

Advantages for Beginners:

  • Simple syntax
  • Good defaults
  • Extensive documentation
  • Active community

Introduction to brms

What is brms?

Bayesian Regression Models using Stan

— more flexible than rstanarm.

Key Features:

  • Extremely flexible model specification
  • Supports complex hierarchical structures
  • Distributional regression (model σ, not just μ)
  • Custom families and link functions
  • Generates Stan code on the fly

Installation:

install.packages("brms")
library(brms)

Basic Syntax:

# Standard regression
model <- brm(y ~ x, data = mydata)

# Hierarchical model
model <- brm(y ~ x + (1 | group), data = mydata)

When to Use brms:

  • Need custom distributions
  • Complex random effects structures
  • Non-linear models
  • Want maximum flexibility

Model Interpretation:

Fixed Effects:

  • length: Average effect of fish size on mercury across all lakes

Random Effects:

  • (1 | lake): Each lake has its own intercept
  • sd(Intercept): How much lakes vary in baseline mercury
  • This is the key quantity!

Residual:

  • sigma: Within-lake variation sigma `: Within-lake variation

Prior Selection for Hierarchical Models

Why Priors Matter:

In hierarchical models, priors are particularly important for:

  • Variance parameters (σ_α, σ_y)
  • Group-level effects with limited data
  • Complex models with many parameters

Default vs Custom Priors:

rstanarm Defaults (Usually Good):

  • Weakly informative
  • Scaled to data
  • Rarely need to change

brms Requires Specification:

  • More flexible
  • Should think about priors
  • Can use get_prior() to see options

Prior Selection Guidelines

For Fixed Effects (β):

prior(normal(0, 5), class = b)
  • Normal(0, 5) is weakly informative
  • Allows wide range but not absurd values
  • Adjust scale based on response variable units

For Standard Deviations (σ):

prior(cauchy(0, 1), class = sigma)
prior(cauchy(0, 1), class = sd)
  • Half-Cauchy is standard choice
  • Heavy tails allow large values if data support it
  • Scale should relate to expected variation

For Correlations:

prior(lkj(2), class = cor)
  • LKJ prior for correlation matrices
  • η = 2 is weakly informative (favors no correlation)
  • η = 1 is uniform (all correlations equally likely)

Principle: Weakly informative priors that regularize but don’t dominate data

Prior Sensitivity Analysis

Always Check Prior Influence:

# Fit with different priors
model_weak <- brm(
  y ~ x + (1 | group),
  prior = prior(normal(0, 10), class = b)

model_strong <- brm(
  y ~ x + (1 | group),
  prior = prior(normal(0, 1), class = b)

# Compare posteriors

  • Are posteriors similar? Good! (Data overwhelms prior)
  • Very different? Prior is too strong OR insufficient data
  • If conclusions change: report sensitivity, get more data

Crossed vs Nested Random Effects

Nested: Groups within groups

  • Sites within regions
  • Students within schools
  • Plots within forests
# Syntax
(1 | region/site)
# or equivalently
(1 | region) + (1 | region:site)

Crossed: Independent grouping factors

  • Sites AND years (each site measured each year)
  • Subjects AND stimuli (each subject sees each stimulus)
  • Raters AND items (each rater rates each item)
# Syntax
(1 | site) + (1 | year)

How to Tell:

  • Nested: Each site belongs to exactly one region
  • Crossed: Each combination of site×year is possible

Environmental Examples:

  • Nested: Transects within sites within watersheds
  • Crossed: Sites measured across multiple years
  • Mixed: Sites within regions, measured across years

Intraclass Correlation Coefficient (ICC)

What is ICC?

Proportion of total variance due to grouping structure.

Formula:

ICC = σ²_group / (σ²_group + σ²_residual)

Interpretation:

  • ICC = 0: Grouping doesn’t matter (no clustering)
  • ICC = 0.05: 5% of variance is between groups
  • ICC = 0.50: Half of variance is between groups
  • ICC = 1.0: All variance is between groups

Practical Meaning:

  • High ICC: Groups are very different, group identity is important
  • Low ICC: Groups are similar, might not need hierarchical model
  • ICC > 0.05: Generally use hierarchical model

Intraclass Correlation Coefficient (ICC)

In R:

# Calculate ICC
performance::icc(model)

# Or manually from output
var_group <- 0.8^2  # SD of group effect
var_resid <- 0.3^2  # Residual SD
icc <- var_group / (var_group + var_resid)

Model Selection: Practical Considerations

Don’t Rely Only on Metrics!

Consider:

  1. Scientific Plausibility
    • Does model make sense?
    • Consistent with theory?
  2. Interpretability
    • Can you explain results?
    • Simpler is often better
  3. Predictive Performance
    • How well does it predict new data?
    • Check posterior predictive checks
  4. Computational Feasibility
    • Does it converge?
    • Reasonable run time?
  5. Robustness
    • Sensitive to priors?
    • Stable across subsets?

Best Practice: Fit multiple reasonable models, compare, report sensitivity

Common Pitfalls and Solutions

1. Convergence Failures

  • Problem: Rhat > 1.1, divergent transitions
  • Solutions:
    • Run more iterations
    • Reparameterize model
    • Use stronger priors
    • Check for multicollinearity

2. Too Many Random Effects

  • Problem: Model doesn’t converge, huge uncertainties
  • Solutions:
    • Simplify random effects structure
    • Need more data per group
    • Consider some effects as fixed

Common Pitfalls and Solutions

3. Complete Separation

  • Problem: Perfect prediction in logistic regression
  • Solutions:
    • Use informative priors (Bayesian advantage!)
    • Combine rare categories
    • Get more data

4. Overfitting Random Effects

  • Problem: Random effects for groups with 1-2 observations
  • Solutions:
    • Groups need ≥3 observations ideally
    • Combine small groups
    • Use stronger priors

Reporting Bayesian Hierarchical Models

Essential Components:

1. Model Specification

  • Full model equation
  • Distributional assumptions
  • Random effects structure

2. Prior Choices

  • State all priors
  • Justify choices
  • Report sensitivity analysis

3. Convergence Diagnostics

  • Rhat for all parameters
  • Effective sample sizes
  • Any convergence issues

4. Fixed Effects Results

  • Posterior medians and 95% CIs
  • Probability statements where relevant
  • Effect sizes and interpretation

5. Random Effects

  • Standard deviations with CIs
  • ICC if relevant
  • Interpretation of variance components

6. Model Comparison

  • LOO or WAIC if comparing models
  • Posterior predictive checks

Example Write-Up

Methods:

“We fit a Bayesian hierarchical linear model with random intercepts for lakes to account for repeated measures within lakes. The model included fish length as a fixed effect. We used weakly informative priors: Normal(0, 5) for fixed effects and Half-Cauchy(0, 2.5) for variance parameters. We fit the model using stan_glmer from the rstanarm package with 4 chains of 2000 iterations each (1000 warmup). Convergence was assessed using Rhat statistics (all < 1.01) and visual inspection of trace plots.”

Results:

“Fish length had a positive effect on mercury concentration (β = 0.52, 95% CI [0.34, 0.71], P(β > 0) > 0.999), with each additional cm associated with 0.52 µg/g more mercury. Lakes varied substantially in baseline mercury (SD = 0.78, 95% CI [0.53, 1.15]), with the intraclass correlation coefficient indicating that 58% of total variance was attributable to differences between lakes. Posterior predictive checks indicated good model fit (Figure S1).”

Advanced Topics: Non-Linear Hierarchical Models

When Relationships Aren’t Linear:

# Non-linear growth curve
nl_model <- brm(
  bf(
    height ~ a * (1 - exp(-k * age)),
    a ~ 1 + (1 | species),
    k ~ 1 + (1 | species),
    nl = TRUE
  ),
  data = growth_data,
  prior = c(
    prior(normal(100, 20), nlpar = "a"),
    prior(normal(0.1, 0.05), nlpar = "k", lb = 0)
  )
)

Applications:

  • Growth curves (von Bertalanffy, logistic)
  • Dose-response relationships
  • Michaelis-Menten kinetics
  • Population dynamics

Advantages:

  • Mechanistic interpretation
  • Extrapolation based on theory
  • Species/site-specific parameters

Advanced Topics: Distributional Regression

Model More Than the Mean:

# Model both mean AND variance
dist_model <- brm(
  bf(
    mercury ~ length + (1 | lake),
    sigma ~ length + (1 | lake)
  ),
  data = fish_data,
  family = gaussian()
)

What This Does:

  • Mean mercury depends on length and lake
  • Variance ALSO depends on length and lake
  • Some lakes more variable than others
  • Variability might increase with length (heteroscedasticity)

Applications:

  • When variance differs across groups
  • Heteroscedasticity
  • Understanding variability patterns
  • Risk assessment (variance matters!)

Putting It All Together: Complete Workflow

Step-by-Step Process:

1. Identify Structure

  • What are the grouping variables?
  • How are they related (nested, crossed)?
  • What level are predictors measured at?

2. Specify Model

  • Random intercepts, slopes, or both?
  • Fixed effects of interest
  • Appropriate distribution family

3. Choose Priors

  • Weakly informative as default
  • Stronger if prior knowledge available
  • Document choices

4. Fit Model

  • Use rstanarm for simplicity or brms for flexibility
  • Check convergence (Rhat, ESS, traces)
  • Run longer if needed

5. Check Model

  • Posterior predictive checks
  • Residual diagnostics
  • Prior sensitivity

6. Interpret and Report

  • Fixed effects with uncertainty
  • Random effects variation
  • Biological meaning
  • Visualizations

Complete Workflow Example (Code)

library(rstanarm)
library(tidyverse)
library(bayesplot)

# 1. Explore data structure
summary(mydata)
table(mydata$site)  # How many obs per site?

# 2. Fit model
model <- stan_glmer(
  response ~ predictor1 + predictor2 + (1 + predictor1 | site),
  data = mydata,
  family = gaussian(),
  chains = 4,
  iter = 2000,
  seed = 123
)

# 3. Check convergence
summary(model)  # Look at Rhat
mcmc_trace(model, pars = c("(Intercept)", "predictor1", "predictor2"))

# 4. Posterior predictive check
pp_check(model, type = "dens_overlay", ndraws = 50)

# 5. Extract results
fixef(model)
ranef(model)
performance::icc(model)

# 6. Visualize
plot(model)
mcmc_areas(model, pars = c("predictor1", "predictor2"))

# 7. Predict
new_data <- expand.grid(
  predictor1 = seq(min(mydata$predictor1), max(mydata$predictor1), length = 100),
  predictor2 = mean(mydata$predictor2),
  site = "Site1"
)
predictions <- posterior_epred(model, newdata = new_data)

Decision Guide: When to Use What

Use Standard Regression When: - No clustering or repeated measures - All observations truly independent - Single level of observation

Use Hierarchical Model When: - Nested or grouped data structure - Repeated measures - Unbalanced group sizes - Want to generalize to new groups - Interested in group-level variation

Use Random Intercepts When: - Groups differ in baseline/mean - Same relationship across groups - Most common hierarchical model

Use Random Slopes When: - Relationship varies by group - Sufficient data per group (n ≥ 5-10) - Theoretical reason to expect variation

Use rstanarm When: - Want simple, standard models - Getting started with Bayesian - Need fast computation

Use brms When: - Need flexibility - Complex random effects - Custom distributions - Distributional regression

Summary: Key Takeaways

Core Concepts: 1. Clustering matters: Ignoring structure leads to wrong conclusions 2. Partial pooling: Best of complete and no pooling approaches 3. Shrinkage: Automatic regularization toward population mean 4. Information sharing: Small groups borrow strength from larger groups

Practical Benefits: - Correct standard errors - Better predictions for groups with little data - Can predict for new, unobserved groups - Explicitly models and estimates sources of variation - Handles unbalanced data elegantly

When to Use: - Nested/grouped/repeated measures data - Interest in group-level variation - Predictions for new groups - Unbalanced sample sizes - Common in environmental science!

Bayesian Advantages: - Natural hierarchical framework - Handles small samples well - Full uncertainty quantification - Direct probability statements - Flexible and extensible

Common Questions

Q: How many groups/observations per group do I need? - Minimum: ~5-10 groups for stable variance estimates - Per group: 2-3 minimum, 5-10 ideal for random slopes - Unbalanced is OK! (that’s a strength of hierarchical models)

Q: Random or fixed effects? - Fixed: Specific levels you care about (e.g., specific treatments) - Random: Sample from population, want to generalize - If unsure: start with random, it’s usually safer

Q: How do I know if I need random slopes? - Theory suggests varying relationships - Test with model comparison (LOO/WAIC) - Plot data by group—do slopes look different? - Need enough data per group

Q: Do I need to worry about p-values? - No! Use credible intervals and probability statements - P(β > 0 | data) is more interpretable than p-value - Focus on effect sizes and uncertainty

Q: How do I deal with convergence problems? - Run more iterations - Use informative priors - Reparameterize model - Check for multicollinearity
